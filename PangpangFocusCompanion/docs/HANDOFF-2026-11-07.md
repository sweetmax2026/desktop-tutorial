## 测试工具、日志与下一步

建议先跑不影响用户操作的检查，再集中安排需要用户参与的一组实测：

```sh
python3 tests/LifecycleScoringChecks.py
zsh scripts/check-focus-flow.sh
zsh scripts/check-sandbox.sh
cd feedback-service && npm ci && npm test
```

- 编译原生检查需要Xcode编译插件。受限执行环境若出现SwiftUIMacros或sandbox-exec错误，先区分环境权限与代码错误，必要时用正常授权的构建路径。
- `scripts/build-release-acceptance.sh`生成独立完整测试App。它使用真实AppDelegate、真实时间、单独bundle/defaults，禁用真实App监控和冲突全局快捷键，反馈URL留空。
- 非沙盒测试域`pangpang.release.acceptance.v1`，测试记录可用于验收，不能与正式记录混用。测试App可能仍运行，先查看当前状态；不向正式App注入测试数据。
- `AcceptanceLifecycleRecorder.swift`只记系统事件、时间、sessionID、截止时间和数量到`/private/tmp/pang-acceptance-lifecycle.jsonl`，不启动计时。脚本`check-acceptance-lifecycle.py`只核对入睡事件本身处于focus的那一轮。不要再从更早的任意focus行拿基线。
- 睡眠测试应让用户在本机点测试App的“开始专注”，立即选择苹果菜单“睡眠”，超过截止时间后由用户唤醒并解锁；首次尝试没有同一轮重叠，不能拿来报PASS。不要远程提前开始后长时间等待用户阅读；不要代输解锁密码，也不反复开关旁白。
- 截止前唤醒只证明截止时间保持，不等于已经验证截止后结算；系统“接受通知”不等于横幅实际出现；源码分支不等于辅助功能实机通过。
- 本机验收证据位于原项目`design/release-acceptance-2026-11-05/`及若干`build/sandbox-check-*`。含系统设置/安装版截图，**不随代码上传**。可据报告复现实验，不要为了补图重新读出正式用户数据。
